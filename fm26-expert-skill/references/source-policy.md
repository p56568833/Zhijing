# 来源与时效策略

## 来源优先级

1. 游戏内当前存档画面、规则页、版本号和用户提供的数据；
2. FootballManager.com 官方功能页、新闻、支持文章；
3. Sports Interactive 官方论坛中 SI Staff/Admin 发布的公告、Known Issues 和 Bug Tracker 状态；
4. 平台官方商店/支持页（Steam、Xbox、PlayStation、Nintendo、Netflix）；
5. 可复现且说明版本、样本和方法的社区测试；
6. 攻略站、视频、论坛经验帖；只作线索，不单独支撑精确结论。

维基、数据库网站和球员搜索站可用于找候选，但不能证明用户存档中的属性、价格、兴趣或随机潜力。

## 何时必须联网

- 补丁版本、发布日期、热修复、Known Issues、平台可用性；
- FM26 新特性、菜单路径或某功能是否被删除/恢复；
- 球员/俱乐部当前数据库数据、现实转会、授权与联赛规则；
- 用户要求“最新”“现在”“确定”“官方怎么说”；
- 自己对事实没有足够把握，或资料可能来自 FM24 及更早版本。

## 搜索方法

优先限定域名并使用英文官方术语：

- `site:footballmanager.com/fm26/features <feature>`
- `site:footballmanager.com/news FM26 <topic>`
- `site:community.sports-interactive.com FM26 <version or issue>`
- `site:community.sports-interactive.com/bugtracker "Football Manager 26" <symptom>`

对战术隐藏机制或社区实验，同时搜索“FM26 + 版本号 + 测试方法”，并检查是否真正测试 FM26 而不是沿用旧版。

## 引用和措辞

- 在相关事实后就近放链接，不堆一个无说明的来源列表。
- 标注核实日期以及平台/版本，例如：“截至 2026-07-11，PC/Mac 版……”。
- 官方未说明底层算法时写“官方未公开”，不要从 UI 文案反推精确公式。
- 多个来源冲突时，以更高优先级和更新日期为准，并简述冲突。
- 社区 Bug 报告只有 SI Staff 确认或状态标为 Known Issue 时，才称为“官方已知问题”；Open 报告只能称“已有用户报告”。

## 故障安全边界

先建议可逆步骤：保存备份、禁用第三方皮肤/模组、验证文件、用新档复现。涉及删除缓存、偏好设置或重装前，说明影响并要求用户备份。不要建议删除存档或覆盖原文件。
